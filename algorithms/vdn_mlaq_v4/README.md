# VDN-MLAQ v4：固定队友的个体价值比较

v4 从隔离后的 v2 派生。全局选边沿用完整状态个体表的和值 `Q_tot = ΣQ_i`。局部选人改用固定队友条件下观察到的探索收益。

1. 全局 UCB 选到虚拟动作时，从临时图已知联合动作中选 `Q_tot` 最大的作为基准。无基准时做全员想象。有基准的入口每五次安排一次全员想象，其余各选一人。
2. 固定另外两人的基准动作，调用原有对话接口让被选人提出替代。解析完整联合动作，核对固定项，并排除临时图和永久记忆里已有的联合搭配。检查动作及后继，添加新转移，随后沿新分支继续搜索。
3. 当轮结束后，在同一张永久图上计算从两条联合边出发的最短已知成功路线。包含第一步时，长度为 `d` 的路线对应价值 `γ^(d-1)`。新分支价值减基准分支价值就是固定队友的动作优势。分支尚无到目标的路径时暂不计算优势，后续轮可重新评价。
4. 单人请求在当轮找到更短成功路线，或从基准无已知成功路径变为替代分支有路径，计一次改善。一次请求内的重试仍算一次尝试，提案、检查和预测的 token 计入请求成本。后续展开计入整轮成本。历史尝试的收益按当轮结果记账，后续动作优势刷新时不重复计数。
5. 统计按 `(目标, 完整状态, 基准联合动作, 智能体)` 保存。先给未试方向机会。均有反馈时，选择 `历史改善率 + sqrt(2 ln(N) / n_i)` 最高者，其中 `N` 和 `n_i` 为同一条件下总尝试数和个人尝试数，含当轮正在等待评价的请求数。若仍有方向只在等待反馈，先按尝试次数选人；相同分数按原智能体顺序决定。

动作优势依赖于队友搭配和当前图的覆盖情况。它的符号及路线是否可达用于判断当轮是否有改善，改善率用于未来选人。全局 `Q_tot` 仍由 v2 的团队 TD 规则学习。一个请求未发现改善，其探索收益记 0，未评价完的替代动作保留未知值。

探索统计、动作对照和有基准的虚拟入口计数随 `lang_tree.pth` 保存，在同批次内跨 case 和难度阶段复用。续跑使用之前完成的 case 快照，若从某难度首个 case 重试则恢复上一难度的备份。旧 v2 图缺少 v4 字段时从空探索统计开始。

`case_result.json` 的 `fixed_teammate` 汇总首次尝试、历史收益选人、等待反馈时选人、两种全员想象及改善次数。每次请求的状态、目标、基准、被选人、结果及 token 见 `simulate/round_*/log.txt` 的 `v4 exploration result`。重跑 case 时原始日志可能追加记录，汇总字段对应本次执行。

## 运行

从项目根目录运行，默认批量任务为 `sort_dialog`。

```bash
nohup python -u algorithms/vdn_mlaq_v4/run_benchmark.py \
  --llm deepseek-v4-flash --compare_q \
  > "vdn_mlaq_v4_$(date +%Y%m%d_%H%M%S).log" 2>&1 &
```

输出为 `data/sort_dialog/vdn_mlaq_v4/<批次>/`。续跑增加 `--epoch vdn_mlaq_v4/<批次>`，使用同一模型和实验配置。`--compare_q` 仍是同图上的 MLAQ / VDN 价值对照，选人记录始终写入日志。

离线验证覆盖 Sort 场景的四种启动与选人分支，以及延迟估值、学习后选择、保存恢复和 Python 3.8 批量入口。实验报告位于“MLAQ 改进”的 `experiments/20261109_v4_fixed_teammate`。完整状态和完整基准键仍可能导致重复样本不足。在线实验需查看 `single_value` 占比，并在相同预算下和随机选人对照。
